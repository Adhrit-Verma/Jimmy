## 0 · Research (2026-10-31)

**Gemini 3.8 Flash** ([model page](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash),
[pricing](https://ai.google.dev/gemini-api/docs/pricing), [OpenAI compatibility](https://ai.google.dev/gemini-api/docs/openai)):
- Model id `gemini-3.8-flash`; text, image, video, audio and PDF in; text out; 1M context.
  Function calling, structured output and streaming work through the OpenAI-compatible endpoint
  `https://generativelanguage.googleapis.com/v1beta/openai/`, the same request format Jimmy
  already sends. Images go as `image_url` data URLs, as Jimmy's vision path already does.
- **Free tier: "Free of charge"** for input and output. Paid: $0.75 / $3.75 per 1M tokens until
  2026-12-31, then double.
- **Thinking can't be turned off**: low / medium (default) / high; `minimal` is an error. Jimmy
  asks for `low` everywhere. Thinking tokens may not count against `max_tokens`
  ([forum](https://discuss.ai.google.dev/t/gemini-3-8-flash-high-does-maxoutputtokens-include-thinking-tokens/181077)).
- **Free-tier limits aren't published.** Google says to read them in AI Studio; third-party sites
  disagree (20 requests a day, or 1,500). Quotas are per project and reset at midnight Pacific.
  Jimmy makes ~70–150 cloud calls on a normal day, so **the free quota may run out**. That
  can't be allowed to break Jimmy (§ A).
- **Privacy: free-tier input may be read by human reviewers** to improve Google's products
  ([terms](https://ai.google.dev/gemini-api/terms)); paid use isn't. Google advises against
  sending personal data to the free tier. Jimmy sends screen text and, for "look", screenshots
  (faces already blurred; excluded windows never captured). **The human decides** (§ A.4).
- **Thought signatures:** Gemini 3 rejects (HTTP 400) a multi-step tool conversation whose
  earlier tool calls lost their `extra_content.google.thought_signature`
  ([docs](https://ai.google.dev/gemini-api/docs/generate-content/thought-signatures)). Jimmy's agent
  passes tool calls back exactly as received, so they survive; a call that didn't come from
  Gemini (a step answered by the backup model) gets Google's documented dummy signature.
- One known report: tool calls get suppressed when the prompt holds reflective first-person
  prose ([forum](https://discuss.ai.google.dev/t/gemini-3-8-flash-tool-calls-are-suppressed-when-the-prompt-contains-reflective-first-person-text-regression-vs-3-5/180934)).
  The 130-command eval will show whether it bites Jimmy.

**"Smart UI" is OpenAI's Intelligent UI** (GPT-6 in ChatGPT, 2026-10-07;
[coverage](https://the-decoder.com/chatgpt-with-gpt-6-ditches-mostly-text-output-for-interactive-ui-with-charts-buttons-and-mini-apps/),
[how it works](https://www.openui.com/blog/how-chatgpt-intelligent-ui-works)): the model answers with
text, visuals and interactive pieces (buttons, forms, charts, sliders, small tools), chosen per
question; **plain text when that's best**. The architecture is "model-generated, server-compiled,
client-executed". OpenAI's own UI guidelines for in-chat components
([UX principles](https://developers.openai.com/apps-sdk/concepts/ux-principles),
[UI guidelines](https://developers.openai.com/plugins/concepts/ui-guidelines)) give the rules Jimmy
adopts:
1. a component must earn its place: would plain text be worse?
2. at most two actions on a card (one primary);
3. no scrolling inside a card; anything bigger opens the full view (Jimmy: the timeline window);
4. no long static text and no sensitive data in a card;
5. look like the host (Jimmy's existing surface, not a new style).

## A · Gemini as a provider, with a backup that can't run out (D54)

1. `JIMMY_PROVIDER=gemini`: key `GEMINI_API_KEY` (or `GOOGLE_API_KEY`), the endpoint above,
   `gemini-3.8-flash` for chat, tools and vision.
2. **Gemini's request shape** in `jimmy/llm.py`: `reasoning_effort: "low"`, no `temperature`
   (Gemini 3 wants its default), no NVIDIA template switch, room for thinking in `max_tokens`.
   Tool calls keep their signature; a call without one gets the documented dummy; and
   `extra_content` is stripped before a request goes to a non-Gemini endpoint.
3. **The backup.** With an NVIDIA key present, every Gemini call that fails with quota (429),
   unavailability (5xx, timeouts, unreachable) or an empty answer goes to NVIDIA's models
   instead, *in the same call*, and the client stays on NVIDIA until quota could be back (the
   next midnight Pacific for a daily quota; one minute for a burst limit or an outage). One
   console line says so. A stream that has already spoken never switches mid-sentence.
4. **Privacy switch:** `GEMINI_SCREENSHOTS` (default **off**). "Look at my screen" sends
   screenshots to NVIDIA's vision models unless the human turns it on; text goes to Gemini.
   `jimmy doctor` prints the free-tier note.
5. Tests: the request shape, signatures kept and dummied, the backup on 429 / 503 / timeout,
   staying on the backup until reset, no switch mid-stream, screenshots routed by the switch.
   **Live (needs the key):** `eval_agent.py` (130 commands), `eval_trajectory.py` (8 tasks),
   first-word latency. Gemini replaces gpt-oss for the agent only if it is at least as right
   and not much slower; otherwise Gemini answers and NVIDIA picks tools.

## C · Ask only when unsure (D55, the human's amendment to non-negotiable 1)

`AUTONOMY = "when_unsure"` (or `"always"` = today's behaviour). A screen action runs **without a
yes** only if all of these hold, checked in code (`ambient/policy.py`):
1. the policy says *allow* (not risky, not a password box, not a CAPTCHA, not injected text,
   the control still has the name the model gave);
2. it's reversible: a click on a non-risky control, switching / minimizing / maximizing a
   window, typing words the user said into a **search or address box**, Enter in a **search or
   address box**. Enter anywhere else (a chat box sends), closing, opening a site the user
   didn't name: still ask;
3. **Jimmy is sure of the target:** the control's name matches the user's words well
   (`act.score` ≥ 0.6) and no other control is nearly as good (≥ 0.15 behind), or it's the
   only box that takes text when the user asked to type.

Then Jimmy shows the cursor on it and says what it's doing ("Pressing “Search”…"), waits
`AUTO_GRACE_S` (1.2 s, so "stop" works), and does it. **A plan** no longer needs its own yes
when every step it names is on that list; each action is still checked on its own, and the first
one Jimmy isn't sure of or that isn't reversible stops and asks.

**When unsure, Jimmy asks with choices**, not "say yes": "Which one: Search, or Search
settings?", as buttons (§ D) and by voice ("the first one", or the name).

Tests: each rule both ways; the stop window; a plan that runs straight through; a plan that
stops at a risky step; choices answered by button and by voice; `"always"` restores today.

## D · Intelligent UI: templates (D56)

An answer can carry one **UI block**: `{"template": name, "data": {...}}`. Python validates it
(known template, capped sizes, every string cut and shown as text, never HTML); the overlay
renders it from a registry (`overlay/src/Templates.jsx`). Captured text stays untrusted:
templates only ever display it.

| Template | When | Who fills it |
|---|---|---|
| `steps` | a plan, running: each step pending / running / done / failed, and Stop | code |
| `choice` | Jimmy isn't sure: 2–4 options as buttons; voice works the same | code |
| `confirm` | a risky action: what, why it's risky, [Do it] [Cancel] | code |
| `list` | reminders, goals, memories, open windows | code |
| `table` | a comparison or structured facts (≤ 5 columns × 8 rows) | the model, via `reply` |
| `checklist` | how-to steps the user follows themselves (ticks are local) | the model, via `reply` |
| `chart` | numbers worth seeing (bars, ≤ 8) | the model, via `reply` |

The model gets one optional `ui` argument on `reply`, with the rule "only when plain text would
be worse". Code-written templates follow invariant 9's spirit: lines Jimmy shows about its own
actions are written by code.

Tests: validation (unknown templates dropped, sizes capped, strings cut, numbers checked),
every code template emitted at the right moment, button actions reaching the Asker, the overlay
build and a `--demo --snapshot` of each template.

## E · Step playback (D57)

- The `steps` card updates live as a plan runs (from the agent's own step events): the current
  step glows, done steps tick, a failed check turns the step amber with its reason.
- Each action is shown before it happens: the cursor moves to the control and holds
  `STEP_SHOW_S` (0.6 s), then acts. The ✓/✗ check (D48) decides the tick.
- "Stop" (button or voice) ends the run between steps; the card says which steps didn't run.
